# Два резюме разработчика 1С

Две версии по одной странице A4: Junior / Middle с одним годом опыта и Middle / Senior с тремя годами. Содержимое редактируется в `resume_data.json`, после чего `build.cmd` пересобирает PDF. Word, LaTeX и подключение к интернету для сборки не нужны.

## Что открыть

- `output\pdf` - оба готовых PDF и их текстовые копии `junior.txt`, `senior.txt`.
- `resume_data.json` - общий профиль, образование и отдельные тексты двух резюме.
- `build.cmd` - запуск сборки в Windows.
- `build.py` - макет и проверки; менять для обычной правки текста не требуется.
- `assets\fonts` - шрифты IBM Plex Sans и лицензия SIL Open Font License.

PDF содержит обычный выделяемый текст и встроенные шрифты. Цветные блоки и иконки нарисованы векторно. Это не скан и не интерактивная PDF-форма: содержимое меняется в исходном JSON. Email и Telegram в формате `@username` становятся кликабельными ссылками.

## Как изменить текст

Все поля внутри `person` необязательны: пустая строка `""`, строка из пробелов или отсутствие ключа скрывают соответствующее поле в обоих PDF. Телефон и `work_format` сейчас оставлены пустыми по запросу пользователя. Чтобы вернуть поле, впиши значение и пересобери резюме. Например, `"phone": "+7 999 123-45-67"` или `"work_format": "Удалённая работа"`. Лишние разделители не выводятся, полностью пустая строка контактов убирается. Значения в квадратных скобках считаются обычным текстом и отображаются; для скрытия их нужно заменить на `""`. Все значения должны оставаться строками в кавычках.

Возраст задаётся общим полем `person.age` и выводится рядом с городом в обоих резюме. Указывай возраст с единицей, например `"age": "24 года"`. Чтобы скрыть возраст, оставь `"age": ""`. Возраст не вычисляется автоматически и не меняет указанную продолжительность опыта.

1. Открой `resume_data.json` в любом редакторе UTF-8, например VS Code.
2. В `person` отредактируй имя, город, возраст и контакты. Уже заполненные данные сохранены. Для Telegram можно написать `@username`. Эти поля используются в обоих резюме. В `work_format` можно указать формат работы или оставить пустую строку.
3. В `resumes.senior.jobs[0].company` замени `[НАЗВАНИЕ ВТОРОЙ КОМПАНИИ]`.
4. При необходимости отредактируй `summary` (короткий профиль), `skills` (группы навыков), `jobs` (опыт) и общий список `education`. Каждый элемент `bullets` станет отдельным пунктом.
5. Сохрани файл и запусти сборку. Результаты появятся в `output\pdf` рядом со скриптом.

В JSON нужно сохранять двойные кавычки и запятые между элементами. Двойная кавычка внутри текста записывается как `\"`; удобнее использовать русские «кавычки». Для добавления пункта скопируй соседнюю строку. Даты работы имеют формат `06.2023-06.2024`.

В опыте каждый пункт сразу описывает действие, без конструкции «короткий заголовок: пояснение». Названия групп в блоке навыков нужны для быстрого просмотра. Длинное тире и другие типографские тире при сборке заменяются обычным дефисом.

### Где редактировать каждую версию

| Часть JSON | Где появится изменение |
| --- | --- |
| `person`, `education`, `achievements` | В обоих резюме |
| `resumes.junior` | Только в резюме с одним годом опыта |
| `resumes.senior` | Только в резюме с тремя годами опыта |
| `layout` | Оформление обоих резюме |

В каждом резюме `filename` задаёт имя PDF, `title` должность, `level` уровень, `experience_label` строку о стаже. Профиль `summary` может содержать несколько абзацев: разделяй их последовательностью `\n` внутри строки JSON.

### Как менять вертикальные списки стека

Каждая группа в `skills` содержит заголовок `label`, имя иконки `icon` и список `items`. При `layout.compact_skills: false` каждый элемент списка выводится с новой строки. Сейчас включён компактный режим `true`: элементы группы соединяются через «·» и переносятся внутри колонки, чтобы рядом поместились достижения. Например:

```json
{
  "label": "Данные",
  "icon": "database",
  "items": [
    "Язык запросов 1С",
    "СКД",
    "PostgreSQL · MS SQL Server"
  ]
}
```

Чтобы разделить технологии в исходнике, замени одну строку двумя: `"PostgreSQL", "MS SQL Server"`. Для групп предусмотрены иконки `platform`, `database`, `exchange`, `git`. Названия технологий остаются текстом и доступны для поиска. Старый формат группы с полем `text` вместо `items` тоже поддерживается.

## Достижения

Общий список `achievements` используется в обоих резюме и выводится под образованием. Каждый элемент содержит название `title` и результат `result`, который выделяется полужирным. Например:

```json
"achievements": [
  {
    "title": "Всероссийская олимпиада «Высшая проба» по экономике",
    "result": "финалист"
  }
]
```

Чтобы скрыть весь блок, задай `"achievements": []` или удали ключ `achievements`. Название и результат каждого добавленного достижения должны быть непустыми строками. Значок награды отключается вместе с остальными иконками через `show_icons`. Размер текста наследуется от `education_size` и `education_leading`. После редактирования запусти `build.cmd`.

## Оформление

В шапке расположены имя, должность, уровень, стаж и контакты. Небольшой жёлтый знак «1С» выделяет специализацию. Слева на светлом фоне идут четыре группы навыков, образование и достижения, справа профиль и опыт работы. Даты выделены лёгкой подложкой. Палитра сочетает тёмный текст, зелёный акцент и небольшие тёплые детали.

Настройки в `layout` общие для двух версий:

| Настройка | Текущее значение и назначение |
| --- | --- |
| `show_icons` | `true`, показывать линейные иконки; `false` скрывает их |
| `show_1c_badge` | `true`, показывать знак «1С»; `false` скрывает его |
| `sidebar_width` | `180` pt, ширина левой колонки |
| `column_gap` | `18` pt, расстояние между колонками |
| `page_margin` | `33` pt, поля страницы |
| `body_size`, `body_leading` | `10.25` и `12.25` pt, основной текст и межстрочный интервал |
| `skills_size`, `skills_leading` | `9` и `10.5` pt, группы навыков |
| `sidebar_padding` | `8` pt, внутренние поля боковой колонки |
| `compact_skills` | `true`, компактный текст внутри каждой группы; `false` возвращает отдельные строки и может потребовать сокращения текста для одной страницы |
| `education_size`, `education_leading` | `9` и `10.8` pt, образование |
| `colors` | Цвета в формате `#RRGGBB`; `blue` и `green` сейчас используют один зелёный акцент |

Размеры задаются в типографских пунктах: 72 pt = 1 дюйм. Иконки нарисованы локально в `build.py` в едином стиле. Знак «1С» типографический, не файл официального логотипа. Отдельные логотипы каждой технологии не используются. Переключатели меняют только оформление, текст остаётся доступным. Ключ `education_bg` сохранён для совместимости; в текущем макете образование лежит на общем фоне `skills_bg`.

## Команда сборки

В PowerShell из любой папки:

```powershell
& "F:\Курсы 1С\Собеседования\Резюме 1С\build.cmd"
```

В cmd.exe:

```bat
"F:\Курсы 1С\Собеседования\Резюме 1С\build.cmd"
```

Если папку перенесли, замени путь или запусти `build.cmd` из Проводника. Из самой папки в PowerShell достаточно `./build.cmd`. Чтобы увидеть сообщение об ошибке, удобнее запускать из терминала.

Пересобрать только одну версию:

```powershell
& "F:\Курсы 1С\Собеседования\Резюме 1С\build.cmd" --only junior
& "F:\Курсы 1С\Собеседования\Резюме 1С\build.cmd" --only senior
```

При запуске без аргументов пересобираются обе версии. Команда завершает работу с кодом `0` при успехе и ненулевым кодом при ошибке. Старые PDF перезаписываются после успешной подготовки и проверки выбранных документов в памяти. При ошибке в тексте или переполнении страницы существующие PDF сохраняются. Ошибка записи, например открытый файл, может прервать замену отдельных результатов.

После успешной сборки дополнительно обновляются публичные копии для сайта:

- `public\resume-1c-junior.pdf`
- `public\resume-1c-senior.pdf`

Эти имена специально короткие и стабильные для ссылок в Telegram. Локальные PDF с русскими именами в `output\pdf` остаются для просмотра и архива.

## Публикация по постоянным ссылкам

Рекомендуемый вариант - отдельный приватный или публичный GitHub-репозиторий с GitHub Pages. В репозиторий кладутся исходники резюме, шрифты, `resume_data.json`, `build.py`, папка `public` и workflow `.github\workflows\pages.yml`. При каждом push в `main` GitHub Actions устанавливает зависимости, запускает `python build.py`, берёт папку `public` и публикует её в GitHub Pages.

После настройки ссылки будут такими:

```text
https://<github-user>.github.io/<repo>/resume-1c-junior.pdf
https://<github-user>.github.io/<repo>/resume-1c-senior.pdf
```

Страница с выбором двух версий:

```text
https://<github-user>.github.io/<repo>/
```

Первые действия в PowerShell из этой папки:

```powershell
cd "F:\Курсы 1С\Собеседования\Резюме 1С"
git init
git branch -M main
git add resume_data.json build.py build.cmd requirements.txt README.md assets public .github publish.ps1 .gitignore
git commit -m "Initial resume site"
git remote add origin https://github.com/<github-user>/<repo>.git
git push -u origin main
```

На GitHub открой репозиторий: `Settings` -> `Pages` -> `Build and deployment` -> `Source` -> `GitHub Actions`. Workflow уже лежит в комплекте.

Обычное обновление после правок JSON:

```powershell
cd "F:\Курсы 1С\Собеседования\Резюме 1С"
.\publish.ps1 -Message "Update resume text"
```

Скрипт пересоберёт оба PDF, покажет git-статус, сделает commit и push. После завершения GitHub Actions старые ссылки начнут отдавать новые PDF. Если нужно обновить только локальные файлы без публикации, запускай обычный `build.cmd`.

Важно: GitHub Pages публикует сайт в интернет. Даже если репозиторий приватный и тариф позволяет Pages для приватного репозитория, сам Pages-сайт может быть доступен публично. Не выкладывай туда телефон, email, Telegram или биографические детали, которые не готов отправлять всем по ссылке.

## Если текст перестал помещаться

Если Windows запрещает заменить основной PDF (например, он открыт в просмотрщике), сборщик сохраняет файл с суффиксом ` - обновлено.pdf` и сообщает его путь. Закрой основной PDF и повтори сборку, чтобы обновить обычное имя. Если дополнительная копия тоже недоступна для замены, сборка завершится с ошибкой. Фактические имена созданных файлов записываются в `verification.json`.

Макет рассчитан на полную страницу с полями 33 pt, примерно 11,6 мм. Основной шрифт 10,25 pt, межстрочный интервал 12,25 pt. Сборщик не уменьшает основной шрифт автоматически и не переносит остаток на вторую страницу: он сообщает, насколько превышена высота.

Сначала сократи повторение в профиле или один из длинных пунктов. Изменение одного слова иногда убирает лишний перенос. В трёхлетней версии оставляй больше места последней компании. После замены особенно длинного ФИО, названия компании или контактов снова открой PDF и проверь внешний вид.

Сборщик проверяет обе колонки отдельно. Небольшой свободный остаток высоты справа распределяется между блоками; большие пустоты не растягиваются бесконечно. Образование и достижения слева привязаны к нижней части страницы. ФИО длиннее одной строки может использовать меньший размер, до 18 pt. Должность и даты стоят под названием компании. Пустое поле `context` убирает вводный абзац места работы.

## Как устроены две версии

В версии с годом опыта подробно раскрыта работа в ИМБА-ИТ: небольшие задачи, отчёты, загрузки, формы, обмены, обновления и проверка результата. Стек соответствует самостоятельному решению ограниченных задач с ревью старшего коллеги.

В трёхлетней версии первой стоит внутренняя команда торгово-производственной компании. Основной объём посвящён ERP, заказам, B2B/WMS, производительности, выпуску изменений и ревью. ИМБА-ИТ описана короче. Формулировка ведущей роли ограничена подсистемой.

Это две альтернативные версии профиля на момент подготовки, а не исторические резюме на июнь 2024 и июнь 2026. Поэтому ВШЭ присутствует в обеих и указана как продолжающееся обучение до 2029 года. Даты работы сохранены в виде, заданном пользователем.

Образцы опыта основаны на ранее подготовленных моделях работы и последующих правках текста. Персональные данные уже заполнены, название второй компании пока оставлено для замены; вымышленных количественных результатов нет. Перед использованием соотнеси задачи, инструменты и степень самостоятельности со своим опытом. Уровень в строке `level` можно адаптировать к конкретной вакансии.

В трёхлетнем варианте блок навыков включает заданные пользователем актуальные версии: 8.3.27, ERP/КА 2.6, УТ 11.6, понимание 8.5, а также чтение и сопровождение ERP/КА 2.5 и УТ 11.5. Это целевой профиль знаний на момент подачи, а не утверждение, что все эти релизы использовались на каждом месте работы. В описаниях работодателей номера релизов не проставлены. Оставляй конкретные версии в своём резюме по фактическому знакомству с ними.

## Среда и зависимости

Нужен Python 3.10 или новее с `reportlab` и `pypdf`. Шрифты поставляются в комплекте. Сборка проверена в Windows с Python из встроенной среды Codex.

`build.cmd` сначала использует `RESUME_PYTHON`, если переменная задана. Иначе проверяет текущий путь встроенного Python Codex, затем Python в `C:\Users\yvnpl\miniconda3\envs\kokoro`, затем команду `python` из PATH. Полные локальные пути находятся в самом `build.cmd`.

Для другой среды в PowerShell:

```powershell
$env:RESUME_PYTHON = "C:\путь\к\python.exe"
& $env:RESUME_PYTHON -m pip install -r "F:\Курсы 1С\Собеседования\Резюме 1С\requirements.txt"
& "F:\Курсы 1С\Собеседования\Резюме 1С\build.cmd"
```

Установка зависимостей нужна только при их отсутствии. Сам сборщик ничего не устанавливает, не скачивает, не публикует и не запускает в фоне.

## Проверки и файлы результата

При сборке проверяются наличие шрифтов и используемых символов, формат дат, имена выходных файлов, высота страницы, извлекаемый текст, порядок разделов и работодателей. Сохраняются PDF, текстовые копии и `verification.json` с параметрами макета, положением блоков и списком оставшихся заполнителей. При `--only` отчёт описывает только выбранную сборку; другой PDF не меняется.

При подготовке комплекта дополнительно проверены одна страница A4 в каждом PDF, встраивание кириллических шрифтов, сохранность всех текстов, порядок чтения, отсутствие обрезания текста и переполнения. Оба документа отрисованы через Poppler и просмотрены. Проверены запуск `build.cmd` из другой папки и отказ при переполнении без изменения готовых PDF.

После редизайна дополнительно проверены ссылки email и Telegram, границы колонок и зазор перед образованием. Для каждой версии проверены пустые и пробельные значения `person`, отсутствие его ключей, возвращение телефона и формата работы, отдельное и совместное отключение иконок и знака «1С». Список `person` при удалении всех полей оставляй пустым объектом: `"person": {}`.

Порядок записи текста в PDF: шапка, навыки, профиль и опыт, образование, достижения. Локальное извлечение через pypdf сохраняет эту последовательность. Другие системы могут читать двухколоночную страницу иначе. Результат отбора в конкретной ATS не проверялся и зависит от вакансии и системы работодателя. Фактическая биография и достижения не верифицировались.

## Шрифты
